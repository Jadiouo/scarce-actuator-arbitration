# 方向一結果總結：延遲驗證下稽核機制的脆弱性地圖

> 定位：結案紀錄，也是之後實證短文的骨架。只整理，不新增實驗。決策過程以 `docs/direction1-notes.md` 為準；每個數字的出處列在 `docs/direction1-number-audit.md`（JSON 檔與鍵路徑）。
> 記號：表中「±」是 JSON 內第二個值（半寬；stage2 設計文件定義為 1.96 個標準誤，quota 沿用同一做法，JSON 內未另標）。「—」表示該格不適用或 JSON 無對應欄位。

## 1. 問題

**白話。** 一個稀缺的服務者一次只能去幫一個人。請求者自報緊急度，而且有動機誇大。要查證，服務者得親自到場，但到場時狀況已變，所以拿「當時說的」比對「後來看到的」，連誠實的人都會對不上。問題：怎麼查核，才能既抓得到說謊，又不冤枉誠實者？

**正式描述。** 模型：K=3 位 agent、每輪一件物品，偏離者只有 agent 1，其餘誠實。型別在 z 空間為高斯 AR(1)，`z_(t+1)=ρ z_t+√(1−ρ²) ε`，邊際分布為 agent 0 ~ U[0.2,1]、agent 1 ~ U[0,1]、agent 2 的 cdf 為 x²（`docs/stage2_design.md`）。

延遲驗證：t 輪提交報告 v_t 並派遣，τ=1 輪後才觀察到 w=u_(t+τ)。控制量是 **ρ^τ**，即 z 空間相關，下文記 r；誠實者的殘差 `(z_w − r z_v)/√(1−r²)` 精確服從 N(0,1)，所以誠實者被單次門檻 κ 誤判的機率是 Φ(−κ)（`stage2.checks.calibration_honest_flag_rate` 驗證）。r 的格點為 0.5, 0.8, 0.9, 0.99（`quota.meta.rhos`）。

機制族：M0 輪流（忽略回報）；M1 零容忍比對＋永久排除（固定 p 與 AdaAudit 兩版）；M2 到達時稽核＋暫停；M3 派遣時稽核（門檻／信用／CUSUM），懲罰為可寬恕的暫停；M4 低機率即時突襲（每輪機率 ε，該輪物品浪費，目標含得標者）；M5＝M3＋M4；配額族 QM／QT／QE（Jackson–Sonnenschein 與 Escobar–Toikka 式，簡化實作）。

策略族（偏離者）：誠實；常數加價 b；z 位移 dz（含細水長流）；時機型；burst；邊緣灌水（只在差一點就贏時灌剛好夠贏的量；oracle 版知道對手當期出價，無資訊版只用自己的型別與歷史）；自適應（自己模擬稽核）。指標：誠實者後悔 R/T、最大說謊得利 G（與誠實同 seed 配對的平均效用差）、誠實者誤罰率 α。

## 2. 與前人的關係

- **Dai–Blanchard–Jaillet（AdaAudit）**：型別 i.i.d.、稽核得標者並在同輪揭露真實效用、懲罰為永久排除；我們把同一機制放進「型別有持續性＋驗證延遲」的環境，檢驗它的脆弱性。
- **Li（2020）**：靜態模型、驗證完美揭露型別、有限懲罰與雙門檻結構；我們借用的是「有限、可寬恕的懲罰」，但驗證在這裡帶雜訊。
- **Ravikumar–Zhang（2010）**：單一 agent、狀態單調吸收、委託人事前承諾稽核到達率；沒有稀缺資源，也不處理 agent 依時間或距離策略性修改回報。
- **Jackson–Sonnenschein／Escobar–Toikka**：不需貨幣與驗證的配額（linking）機制，是我們必須正面比較的基線；實測結果見第 4、5 節。
- **Probabilistic verification 系列（Caragiannis 等、Ball–Kattwinkel、Ferraioli–Ventre）**：偵測機率可隨謊言距離變化，但需要付款或另設能力假設；我們後來的「雜訊前沿」框架大部分屬此類已知結果，因此依事前條件撤回（第 3 節）。

三個核心前人的共同缺口：沒有處理非單調演化的狀態，也沒有處理 agent 依時間或距離改報。文獻調查並非窮盡。

## 3. 時間線：主張如何被提出、檢驗、被證偽或修正

**(1) 階段 1：零容忍是稻草人。** 預期只有「Markov × τ>0」會退化。實測：只要有延遲，不論 i.i.d. 或 Markov，誠實者都被排除（T=1e5 時 `honest_excl_frac`=1.00），R/T≈0.812（Markov 型別：0.812）；延遲為 τ=5。對照組 τ=0 時 R=0.0。原因是零容忍比對加上不同時刻效用必然不同，近乎顯然，不能當成貢獻（白方事先警告的稻草人）；R/T 的高值還受「全員被排除→效用記 0」的慣例影響，此後兩種 fallback 並列。忠實度檢查：AdaAudit 下 R=2.63，低於 K²=9。

**(2) 階段 1b：「AdaAudit 較耐受」被證偽。** 加入容忍度 δ 後，單次誤判率只由 ρ^τ 決定（代數恆等式，不是發現），動態結果只近似疊合。「AdaAudit 的誠實者衰減較慢所以可能存活」不成立：在 (ρ,τ)=(0.9,1)、T=1e5、δ=0.1 時，兩版的誠實者存活率都是零（固定 p：0.00；AdaAudit：0.00），而 AdaAudit 的稽核次數反而較多（B=16.7 對 9.4）。「固定 δ＋永久排除」的可行區很窄：偏離者 b=0.1、T=1e5、AdaAudit 時，13 個 (ρ,τ) 格 × 7 個 δ 中只有 (ρ,τ)=(0.99,1)、δ=0.2 一點可行（`feasibility["ada|100000|b0.1"].feasible[6][4]`=true）。另一條線索：Markov 型別 τ=0 時，AdaAudit 的 B_T 從理想值 3645.9 升到 5626.1（T=1e5、ρ=0.9），常數放大。

**(3) 階段 2：M3c 看似成立，隨後被邊緣灌水擊敗。** 階段 2 提出 M3c（派遣時稽核＋CUSUM＋可寬恕暫停）。在當時的策略集下（b 族與 z 位移）r=0.9 的最大得利為 G=-0.0118 ± 0.0028，誠實 R/T=0.0067 ± 0.0015，判為「說謊無利」；到達時稽核 M2 則被時機灌水擊敗（r=0.5 時 G=0.2795 ± 0.0004，r=0.99 時 G=0.2805 ± 0.0022，與 r 無關）。紅方加入 oracle 邊緣灌水後，同一機制在 r=0.9 的 G 變為 0.0211 ± 0.0033（策略 `edge_oracle em=0.05`），r=0.5 時為 0.0870 ± 0.0053。「M3c 嚇阻說謊」與據此畫的相圖一併撤回，「M2 被時機灌水擊敗」未被反駁。r=0.8 的通過本來就只是邊緣（G=0.0021 ± 0.0025，T=1e4 時 r=0.8、0.9 都未通過：`eval_pass`=false、false）。

**(4) M4 的漏洞。** 階段 2 的 M4（突襲）通過所有 r，但它從不突襲得標者（`audit_fix.py` 的 `kk != idx`）。後果：r=1 時偏離者仍有 G=0.1811 ± 0.0721；舊版（ε=0.05、rw=0.0）在 r=0.99 的 oracle 邊緣灌水得利為 0.0356 ± 0.0008，修正為「以機率 rw 突襲得標者」後（rw=1.0）變為 -0.1450 ± 0.0039。r=1 的得利因此不是 bug，是設計漏洞。

**(5) F1、F3 成立，理論框架終止。** 重新框架為 Neyman–Pearson 型取捨「誤罰率 α → 最大說謊得利 G*(α, σ_τ)」，白方在看結果前登記否證條件 F1–F4，並禁止第 5 次重新框架。階段 2b 結果：**F1 成立**，G=cσ^s 的指數 s 與 1 的差距超出信賴區間，且隨 α 改變：α=0.005 時 s=1.26 [1.13, 1.39]，α=0.05 時 s=2.18 [1.77, 2.63]；(ρ,τ) 分開掃描（r=0.9、α 目標 0.05）：τ=1 的前沿 G 為 0.0227 ± 0.0060、τ=5 為 0.0221 ± 0.0069，前沿由 r 決定。**F3 成立**：無資訊邊緣灌水只在 r 低時有得利（M3C、α 目標 0.01：r=0.5 為 0.0287 ± 0.0058，約為 oracle 版 0.1235 ± 0.0077 的四分之一；r=0.9 為 0.0011 ± 0.0015，z=1.49；r=0.99 為 -0.0108 ± 0.0064），一階得利主要是 oracle 假象。F2 部分成立（前沿單調、在有限 α 處降到 0），**F4 無法判定**（notes 判定四種檢定表現接近，且沒有下界；此點無 JSON 數字支撐）。依事前規則停止理論方向 (a)，收斂為 (b)：脆弱性地圖實證短文。

**(6) 正面結果與配額基線。** 修正後的突襲（含得標者）在 ε=0.01 時，各 r 都嚇阻說謊且 α=0（例：r=0.5 時 G=-0.0443 ± 0.0094，誤罰 α=0.0000 ± 0.0000），推翻了最初「突襲不可行」的直覺。配額機制擋得住無資訊的小幅灌水（與原本推論相反），擋不住 oracle 策略（第 4 節）。

## 5. 主要發現

**發現 1：直接相信回報與到達時稽核都被灌水大幅擊敗。** NAIVE 的最大得利 G=0.2793 ± 0.0004（r=0.5），M2 為 0.2795 ± 0.0004，且不隨 r 改變（誠實者自己的平均效用只有 0.1875 ± 0.0007）：到達時稽核對「時機灌水」無能為力。（出處：表 4）

**發現 2：派遣時稽核便宜，但只對無資訊說謊者穩。** M3C 的誠實 R/T 在 r=0.5–0.9 約 0.0070 ± 0.0016（r=0.9），誤罰率 α=0.0303 ± 0.0060；無資訊最大得利 ≤ 0.0213 ± 0.0039（r=0.5 最大）。但 oracle 邊緣灌水得利為 0.0211 ± 0.0033（r=0.9）至 0.0870 ± 0.0053（r=0.5），在 r=0.99 仍有 0.0460 ± 0.0015（該格選到 h=8，幾乎不觸發懲罰：α=0.0001 ± 0.0001）。對 ρ 的錯設很敏感：把 r 高估 0.05 時，r=0.9 的誠實者被誤罰 α=0.3073 ± 0.0212，r=0.95 時（假設 r=1，等於型別凍結）α=0.9531 ± 0.0032；低估 0.05 時 r=0.99 的說謊得利由 oracle 設定的 0.0044 ± 0.0059 升到 0.0556 ± 0.0019。（出處：表 4、`stage2b.rho_misspec`）

**發現 3：配額機制擋得住無資訊說謊者，擋不住 oracle，且在型別持續性高時效率損失大。** QM（W=1000）無資訊最大得利 ≤ 0.0048 ± 0.0014（r=0.99），含 oracle 則約 0.0897 ± 0.0003（r=0.5）。效率損失來自誠實報告被改寫：改寫比例從 4.3%（r=0.5）升到 27.0%（r=0.99），誠實 R/T 從 0.0114 ± 0.0001 升到 0.0585 ± 0.0011。（出處：表 4）

**發現 4：低機率突襲（含得標者）最穩健。** 在全部策略（含 oracle 邊緣灌水）下 G=0.0000 ± 0.0000，誠實 R/T=0.0162 ± 0.0001（r=0.5）與 0.0162 ± 0.0002（r=0.99），α=0，不隨 r 變動，不需要知道 ρ；代價是誠實 R/T 比 M3C 高（M3C 在 r=0.9 為 0.0070 ± 0.0016）。成本假設：**在抽象模型中，一次突襲的代價是浪費一輪**（被突襲輪的物品不分配，浪費比例=0.0200 ± 0.0002，即 ε；rw=1、ε=0.01 時誠實 R/T=0.0082 ± 0.0002）。**在空間模型中，這個成本對應的是旅行**（要即時觀察真相，服務者必須實際前往，路徑可被觀察）；此對應尚未在空間模擬中量測。（出處：表 4、`stage2b.eval_rows.M4`）

**發現 5：「雜訊前沿」的普適縮放不成立。** 指數 s 隨 α 變動（第 3 節 (5)，兩個信賴區間不重疊），前沿主要由 r 決定而非另外依賴 τ；原定的理論定理因此無法成立，貢獻轉為實證地圖本身。（出處：`stage2b.scaling_best_family`）

## 6. 限制

- **策略集有限，oracle 策略主導。** 最大得利幾乎都由 oracle 邊緣灌水取得，沒有任何策略被證明是最佳回應。表中的 G(含 oracle) 是 45 種策略的最大值，本身上偏（`quota.meta.G_definition`）。
- **自適應策略偏弱。** 自己模擬稽核的自適應策略常常比簡單的 dz 更差（M3C、α 目標 0.01、r=0.9：自適應得利 -0.0297 ± 0.0078），這更像實作偏弱，不是真的無利可圖。
- **ρ 用 oracle。** M3C、QT 都假設已知 ρ，錯設後果見發現 2；估計器被毒化的情形沒測。
- **K=3。** 結果只在三位 agent 下成立，agent 數與稀缺程度沒有掃描。
- **抽象模型尚未接回環形空間模擬。** 旅行成本與「到場才能查核」的內生性只在文字上對應，沒有量過。
- **部分參數落在網格邊緣。** M3C 在 r=0.5–0.9 選到的暫停長度 L=2500、CUSUM 門檻 h=6（r=0.99 時 h=8），按設計文件 L 的格點上限為 2500、h 的上限為 8（`stage2_design.md`）；M4 的 L 也是 2500。真正的最佳點可能在網格之外。r=0.8 的 M3c「通過」（G=0.0021 ± 0.0025）也只是邊緣通過。
- **贏家詛咒。** 稽核的對象是得標者，其報告被選擇為偏高，所以「v 大於 w」的比對對誠實者也有偏。M3 以 z 空間殘差、對 u_t 條件化吸收了這個偏誤，並以實測誤判率對照 Φ(−κ) 驗證（κ=1.0、r=0.5：實測 0.1608 對 0.1587）；但 M1 的單邊比對沒有這種校正。另外 G 的最大值取自評估 seeds，上偏；無偏的 G_br 另列於 JSON（`Gbr`）。

## 7. 開放問題與下一步

- **方向二（RL 對手）補上策略集的弱點。** 第 6 節的核心弱點是策略手寫且有限（oracle 策略主導、自適應偏弱），每個「通過」都只是「在這個策略集下通過」。訓練 RL 對手對已部署的機制學最佳回應，就能取代手寫策略集，直接檢驗：突襲的 G=0 是否穩固（目前最強的主張）、配額在更強的自適應對手下會多糟、M3C 在 ρ 錯設或估計器被毒化時能否撐住；也可只給對手部分資訊，填補表 4 兩個 G 欄之間的空白。這些都還沒有數字。
- **接回空間模擬。** 把突襲成本由「浪費一輪」換成實際旅行，測在環形空間裡的 R/T 與 G。這是本文結論能否用於實際調度的必要一步。
- **配額加稽核的組合。** 設計文件明列「Q＋audit 組合」未做；配額擋無資訊、突襲擋 oracle，兩者可能互補。
- **F4 與下界。** 四種檢定在 1.5 倍以內，但沒有推導下界；白方判斷即使做出來也很可能是已知結果。
- **待使用者決定：** 實證短文＋作品集 (b) 之後接方向二，或直接轉向方向二或三。
