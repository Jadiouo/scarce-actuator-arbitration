# Direction 2：盲設計者的 4 個人造漏洞（M3C 機制變異）

設計依據：只讀了 `arbitration/gpu/frontier.py` 的 M3C 實作與時序，以及規格 §8.1 的漏洞形式與格式（含 O1/O2/O3/O6/O4 的定義，本文刻意避開這些）。沒有讀任何 agent 觀測或策略結構的檔案。

## 0. M3C 時序摘要（以下設計的依據）

- 第 t 輪：贏家 `idx` 由「回報 v」決定（被暫停者 `t <= susp` 不參賽）。若 `win_eff`，以機率 `p_el` 抽稽核，記下 `pend_a[slot]=idx`、`pend_v[slot]=v_idx`，`slot=(t+tau)%M`。
- 同一輪 t 稍後（`cs=t%M`）結算「tau 輪前」排進來的稽核：用當下真實 `u_t` 當 `wv`，`resid=(zw − rh·zv)/sdh`，只有 `has & elig_ag`（結算當下未被暫停）才更新。
- CUSUM：`Sn=max(S − resid − kref, 0)`，`Sn>tol` 則標記、`S←0`、`susp←t+L`。
- 稽核只針對「得標者」，且是靜默的（agent 看不到）。agent 可觀察：自己的型別 `u`、自己的回報、自己是否得標、自己是否被暫停。tau 與 `p_el` 視為環境常數（若不公開，可由掃描學出）。

通用實作約定：每個變異在 `mech == "M3C"` 分支內，以 `kappa`（knob）參數化；`kappa == 0` 時所有新增分支被 `torch.where(kappa>0, …)` 關閉，張量路徑與原程式相同，逐位元恆等（REQ-S1-05）。新增亂數一律取目前 M3C 未使用的 `Rx[s][sidx][:,0]`（僅 M4 使用），不動既有亂數流。

## V1　SCHED6：贏次週期稽核排程（計數相位）

**類型**：稽核抽樣與計數器相位。需要特定時序組合（自己的得標次數 mod 6）。

### 變異定義
每個 agent 多維護一個得標計數 `nw[B,K]`（初值 0）。抽稽核的機率從固定 `p_el` 改為依「這是第幾次得標」而定：每第 N=6 次得標的稽核機率偏高，其餘偏低，**平均稽核率不變**。

```
N = 6
# 在稽核抽樣處（原：o = win_eff & (Ua[s][sidx] < p_el)）
j      = nw[ar, idx] + 1                      # 這次是該 agent 的第 j 次得標
sched  = (j % N == 0)
p_s    = p_el + kappa * (1 - p_el)            # 排程次：機率升高
p_u    = p_el - kappa * (1 - p_el) / (N - 1)  # 非排程次：機率降低
pp     = where(sched, p_s, p_u)
o      = win_eff & (Ua[s][sidx] < pp)
nw[ar, idx] += win_eff                        # 計數在抽樣之後遞增；不因標記或暫停重置
```
- 平均率檢查：`(1/N)·p_s + ((N−1)/N)·p_u = p_el`，所以稽核總量不變，單看稽核次數或旗標率看不出異常。
- 旋鈕 `kappa ∈ [0, κ_max]`，`κ_max = (N−1)·p_el/(1−p_el)`（此時 `p_u=0`）。
- `kappa=0`：`p_s=p_u=p_el`，恆等。

### 利用方式（只用自己可觀察的）
自己數得標次數（自己的回報與得標結果即可，不需稽核事件）。策略：
```
count = 自己累計得標次數
if (count + 1) % 6 == 0:  report = 真實 u        # 下一次得標是「排程次」，老實
else:                     report = 灌水後的值     # 其餘得標才灌水
```
也就是把謊都放在「低稽核機率」的得標上，把容易被稽核的得標留給誠實回報。誠實時是否得標與灌水無關，因此計數只依實際得標推進。

### 預期得利（推論）
- 灌水得標的被稽核率從 `p_el` 降到 `p_u = p_el − κ(1−p_el)/5`，相對降幅 `κ(1−p_el)/(5·p_el)`。
- 小 κ 時得利約與 κ 成正比：灌水強度上限（受 CUSUM 限制）隨偵測率下降而放寬；在 `κ_max` 達上限（5/6 的得標完全不被稽核），得利趨近「幾乎無稽核灌水」的 5/6，再扣掉誠實的 1/6 得標之機會成本。
- 代價：每 6 次得標中有 1 次要誠實。

### 為什麼手寫族不容易利用
- 常數灌水：每次得標都灌水，排程次（稽核機率偏高）反而被抓；平均稽核率不變，所以淨效果約為零（甚至因 CUSUM 非線性略差）。
- 時機灌水、burst：相位由「絕對時間」決定，與「自己的得標次數 mod 6」無關，只會隨機對到，平均仍是 `p_el`。
- 細水長流、邊緣灌水：灌水量或時機由灌水量／間距決定，同樣與得標計數無關。
- 要利用必須有「得標次數 mod 6」這個狀態，手寫族沒有任何一個帶計數器。注意：公開版歷史窗只有 k=8，無法還原模 6 的相位，要有計數器或長記憶才行；若紅隊工具的特徵不含計數，可能偵測不到，這是此漏洞的「機制可見、特徵不可見」性質（建議登記為類內漏洞但註記需要計數特徵）。

## V2　IDLE-FORGIVE：連續落選寬恕（閒置衰減）

**類型**：計數器衰減。需要特定時序組合（灌水期 → 刻意落選期）。

### 變異定義
每個 agent 維護「連續未得標輪數」`idle[B,K]`。連續落選達 I0=8 輪後，其 CUSUM 每輪乘上 `(1−κ)`（「沒在競爭的 agent 給予寬恕」）。

```
I0 = 8
# 每輪配置之後（在稽核結算之後）：
won_k = onehot(idx) & win_eff[:,None]
idle  = where(won_k, 0, where(elig, idle + 1, idle))   # 被暫停者不累計
cus   = where(idle >= I0, cus * (1 - kappa), cus)       # 每輪衰減，寬恕不觸發標記
```
- 旋鈕 `kappa ∈ [0,1]`：`kappa=0` 時 `cus*1`，恆等。
- 注意：稽核結算仍可在落選期繼續更新 `cus`（tau 輪前灌水的稽核還在路上），衰減只在 `idle>=I0` 之後生效。

### 利用方式
```
loop:
  phase A（灌水期）：持續灌水回報，約 n 輪（n 小於預估的標記時間）
  phase B（休息期）：刻意回報 0（極低回報，確保落選），持續 max(I0, tau) + m 輪
                    （要超過 tau，讓灌水期的稽核都已結算完，之後的衰減才能洗掉 S）
```
- agent 只用到：自己的回報、自己是否得標（確認真的在落選）、自己是否被暫停（若被暫停，表示 n 設太大，下次縮短）。
- n 不需要看到 CUSUM：以搜尋或在線調整（被暫停就減半，沒被暫停就加長）。

### 預期得利（推論）
- 休息一次後 S 乘上 `(1−κ)^(m+1)`；κ→1 時等於「落選 8 輪就清零」，等價於把標記前能灌水的時間重複利用。
- 得利約 `∝ [灌水期占比] × [單位灌水得利]`，灌水期占比 ≈ `n/(n+tau+m+I0)`；κ 越大，n 可以越接近 CUSUM 的標記時間而不被暫停，κ 小時 n 受限且休息期的機會成本吃掉利潤，因此小 κ 可能是負報酬（也就是需要 κ 超過損益平衡點才有可測得利，校準要注意）。
- 代價：休息期整段機會成本（落選），以及每個週期的 tau 結算延遲。

### 為什麼手寫族不容易利用
- 常數灌水：一直得標，`idle` 幾乎不增長，寬恕從不啟動。
- burst、時機灌水：「關閉」期是回報真值，型別高時仍會得標，`idle` 很難連續 8 輪以上；就算偶發，S 在 phase B 前通常尚未被洗到有意義的量。
- 細水長流、邊緣灌水：本來就很少得標或灌水幅度小，自然落選較多，但 CUSUM 本就不累積，沒有東西可洗，得利約為零。
- 要利用必須「刻意低報以保證落選」，這不是任何手寫族的動作（手寫族只會灌水或誠實，沒有刻意放棄贏的選項），而且休息長度要大於 `max(I0, tau)`。

## V3　LAUNDER：大幅正殘差重置（非單調洗白）

**類型**：重置條件。需要型別條件的雙向回報（高型別壓低、低型別灌水）。

### 變異定義
在 M3C 更新處加一條：若這次稽核的殘差 `resid` 超過 `c_r`，視為「強烈誠實證據」，CUSUM 直接重置為 0（不標記、不暫停）。

```
c_r = 2.0 + 2.5 * (1 - kappa)        # 僅 kappa>0 時啟用；kappa∈(0,1]，c_r∈[2.0, 4.5]
# 原：Sn = (Sg - resid - kref).clamp(min=0); el_ = upd & (Sn > tol)
Sn      = (Sg - resid - kref).clamp(min=0)
launder = (kappa > 0) & upd & (resid > c_r)
el_     = upd & (Sn > tol) & ~launder
newS    = where(upd, where(el_ | launder, 0, Sn), Sg)
```
- `kappa=0`：`launder` 恆為 False，恆等。
- 正殘差意味 agent 的回報「遠低於」下一次實現值所預期的水準。誠實時 `resid ~ N(0,1)`，`c_r ≥ 2.0` 讓誠實或隨機混合的稽核只有 ≤2.3% 機率誤觸發，所以「混一點誠實」不會自然得利。
- 原機制中正殘差只是一次性減去，且 S 下限 0，所以「低報」本來就有扣抵上限；這個變異把它放大成全額洗白。

### 利用方式
策略是「依自己的型別 u」的**非單調**回報映射：
```
if u 很高（例如分位數 > 0.85）：  report = 明顯低於 u（例如 u − Δ_down）   # 仍很可能得標，若被稽核則產生大正殘差，洗掉 S
elif u 偏低或中等：               report = 灌水                             # 為了贏而灌水，累積 S
else:                              report = u
```
- agent 可觀察的只有 u、回報、是否得標。「低報仍得標」靠 u 高、對手弱，不需看到他人。
- 洗白是機率事件：每次高型別低報得標的稽核機率 `p_el`，所以洗白頻率 ≈ `p_el × P(高型別得標)`；灌水期的 S 累積要慢於此頻率，才可長期不被標記。

### 預期得利（推論）
- 得利隨 κ 增加：`c_r` 越低，洗白所需的低報深度 Δ_down 越小（`resid ≈ rh·Δ_down_z/sdh + 雜訊`），低報的機會成本（輸掉原本會贏的輪）越小。
- κ 小（`c_r≈4.5`）：需要非常深的低報，容易因此落選，得利接近 0；κ 大：Δ_down 變小，得利上升，但上限由「灌水期被稽核累積 S 的速度 vs 洗白頻率」決定。
- 這是推論；大小與 tau 有關（tau 越大 `rh=rho^tau` 越小，`resid` 對低報的靈敏度越低，洗白越難）。

### 為什麼手寫族不容易利用
- 手寫族全是「單調加性灌水」（回報 ≥ 真值）；沒有任何一個會在高型別時主動低報。
- 常數灌水：永遠不產生正殘差。
- burst、時機灌水、細水長流的「關閉」期是誠實回報，`resid ~ N(0,1)`，超過 `c_r≥2.0` 的機率 ≤2.3%，洗不掉有意義的 S。
- 邊緣灌水依賴他人回報（agent 不可觀察），也不低報。
- 要利用須同時學會「型別高→低報、型別低→灌水」的兩段式映射，這是非單調的策略形式。

## V4　LOSS-SKIP：落選時結算豁免（稽核結算與 tau 的交互）

**類型**：稽核結算時序。需要精確時序組合（灌水輪 t 與刻意落選輪 t+tau 配對）。

### 變異定義
在結算（`cs = t % M`）處，若該 agent 在**結算當輪 t**沒有得標，則以機率 κ 丟棄這次稽核（理由像是「驗證者在該 agent 不在場時無法取得即時比對」）。

```
# 在結算段（已有 ag, has, wv, pv 等）：
won_now = win_eff & (idx == agc)                          # 結算當輪是否得標
skip    = (~won_now) & (Rx[s][sidx][:,0] < kappa)         # 用 M3C 未使用的亂數
upd     = has & elig_ag & ~skip
# 其餘（rh 更新、CUSUM、標記）不變；pend_a[:,cs] = -1 照舊清除
```
- `kappa=0`：`Rx < 0` 恆為 False，`skip` 全為 False，恆等。
- `sxy/sxx` 的更新（以 `has` 為準）保持不變，只丟棄 CUSUM 與標記的更新。

### 利用方式
agent 知道 tau 與自己的得標情形：
```
灌水輪集合 A = { t : 計畫灌水 }
對每個 t ∈ A，在 t+tau 輪刻意回報 0（落選），即使當輪型別很高
其他輪誠實回報
```
- 最簡單的形式：「灌水 a 輪，之後 tau 輪後再落選 a 輪」，週期 ≈ tau + a。（`t+tau` 輪不能同時灌水，因為灌水會得標、稽核便不被豁免。）
- 全部使用自己的回報與得標；不需要稽核事件。

### 預期得利（推論）
- 灌水得標的稽核有 κ 的機率被丟棄（因 t+tau 落選）。得利約 `∝ κ × [灌水占比]`；κ=1 時幾乎免稽核，但灌水占比受限在 ≤50%，且每個灌水輪要對應一個落選輪的機會成本。
- 損益平衡 κ 取決於灌水單位得利與落選輪的損失；小 κ 時可能為負，校準需確認可達 0.003–0.02 的 Δ。

### 為什麼手寫族不容易利用
- 常數灌水：灌水就一直得標，結算時也在得標，`skip` 幾乎不觸發。
- burst：關閉期是誠實回報，會得標的機率不為零，且週期 `(W+H)` 與 `2·tau` 沒有對齊；即使對齊，誠實回報在關閉期仍可能得標，不保證落選。
- 時機灌水、細水長流、邊緣灌水：低灌水量或只在邊緣灌水，本來就常輸，因此會**偶然**吃到少量豁免（我預期這是小的基線得利，非「任何灌水都能利用」），但沒有「刻意在 t+tau 落選」的配對，無法逼近最大得利。
- 要吃滿它必須有「刻意放棄一輪」與「精確的 tau 位移」兩個動作，手寫族都沒有。

## 彙總

| 編號 | 名稱 | 改動位置 | 機制類別 | 需要特定時序組合 |
|---|---|---|---|---|
| V1 | SCHED6 | 稽核抽樣機率 | 得標計數相位 | 是（得標次數 mod 6） |
| V2 | IDLE-FORGIVE | CUSUM 衰減 | 計數器衰減 | 是（灌水期 → 落選 ≥ max(8,tau) 輪） |
| V3 | LAUNDER | CUSUM 重置條件 | 重置 | 否（型別條件的非單調映射） |
| V4 | LOSS-SKIP | 結算時序（tau） | 稽核結算與時序交互 | 是（t 灌水、t+tau 落選） |

與既有算子的區別：O1 是「連勝降稽核機率」，V1 是「得標次數週期的升降機率並保持平均」；O2 是「每次稽核洩漏」，V2 是「連續落選才衰減」；O3 是殘差封頂，V3 是大正殘差觸發重置；O6/O4 是縮短暫停長度，V4 與暫停無關，改的是結算是否發生。

## 校準與風險提醒

1. **小旋鈕可能為負報酬**：V2、V4 都有「刻意落選」的機會成本，在 κ 小時參考策略可能比誠實還差（Δ<0），需在訓練 seeds 上確認 κ 範圍內能達到 `s ∈ {0.003, 0.005, 0.01, 0.02}`；達不到時按 REQ-S1-06 回報 commander，不要自行遞補。
2. **V1 的特徵可見性**：計數相位 mod 6 需要「自己累計得標次數」，公開版歷史窗 k=8 無法還原；是否列為類內漏洞由 commander 決定（或另加計數特徵）。
3. **V3 的 `c_r` 下限**：維持在 ≥2.0 以避免「誠實噪音自然洗白」讓 burst/細水長流意外得利；若校準發現手寫族 Δ 反而變大，應回頭提高 `c_r`。
4. **V4 的基線得利**：邊緣類策略因本來就常落選，會吃到少量豁免；校準時 `G_HW^V` 要以實測為準，已自動計入。
5. 以上得利大小皆為推論，校準以實測為準。
