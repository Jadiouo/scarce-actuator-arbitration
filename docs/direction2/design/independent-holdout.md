# 獨立環境 holdout：執行前協定（2026-10-13）

這是舊主實驗完成後另外登記的一次確認實驗。目的只限於：已固定的公開資訊學習策略，在未用過的環境亂數上，是否仍優於已固定的手寫基準。保留舊 J3、原 test ledger、原規格與全部原始結果；不把這批說成原始預登記的一部分。

## 範圍與停止點

- 主設定僅 M3C、r=0.5，p=0.1、h=6、L=2500、kref=0.5；原 float64 模擬器不變。
- 三個既有 run 全部評估，checkpoint 仍為原 validation 選定的世代 350。主 run 固定為 run0，手寫基準固定為 `dz=0.3`，另帶 honest 對照；不重新搜尋手寫策略或挑選主 run。
- 每個政策跑 64 個全新環境 seeds，T=100000、T_score=97500；不增加 r=0.9、尾端變體、消融或新訓練。
- 一次完成固定樣本量後，無論正、負或不確定都結束這輪並報告。沒有中途顯著性停跑、加樣本、換模型或改門檻。
- 此處「獨立」指環境亂數相對已保存實驗未重複，不是新訓練、外部研究團隊、其他機制或真實機器人的獨立複現。

## 未見過的環境 seeds

基礎 seeds 固定為 41000000–41000063；三條 generator stream 的 seed offset 沿用 0、1000000、2000000。先檢查所有原有 split，並掃描基準 commit `d0fe416` 所追蹤 JSON 與 NPZ checkpoint 的 seed 欄位，確認 base 與 offset 後的集合沒有交集。歷史四流實驗另保守納入 +3000000 的碰撞檢查。保存掃描來源雜湊、範圍、檔案數及限制。

這是對本專案保存紀錄的查核；不能證明不存在完全未保存的外部執行。新 seeds 不會傳入訓練、選模、除錯或預先效能測試。原 `final_eval` 僅管理原本的 test split，不修改；新增獨立入口、manifest 和 ledger 管理這批額外 holdout。

## 主判準

逐 seed 計算 G_RL=(U_RL−U_honest)/97500、G_HW=(U_HW−U_honest)/97500、D=G_RL−G_HW。主要估計量是固定 run0 的平均 D。以 64 個環境 seeds 為獨立單位，報 mean±t(63,0.975)·SD(D)/√64 的配對 95% CI；不把時間點或三個 run 當成 192 個獨立樣本。

新增的實質效應門檻 **δ=0.005 每輪個人效用差**，是這次看新資料前明訂的研究門檻，不是把舊 MDE 解讀成實質重要性，也不是新資料估出的 MDE。沿用先前診斷的 0.005 效應尺度；約為 100000 記分輪累積 500 效用。判定順序：

1. CI_lo>δ：**確認實質優勢**。
2. 否則 CI_lo>0：**確認正優勢，但未確認超過實質門檻**。
3. 否則 CI_hi<δ：**排除達到指定門檻的優勢**；另明列 CI_hi≤0 是否也排除正優勢。
4. 其餘：**證據不足以判定**。

均採嚴格不等號；CI 下界恰等於 δ 不算第 1 類。不能把第 2 類說成等效於零，或把第 4 類說成沒有優勢。舊主實驗的 G-MDE、D-MDE 不改動、不重估、不用來決定本批結論。

64 seeds 的規劃依原 validation：run0 的配對 D 標準差約 0.009417，預期 95% 半寬約 0.002352。若真實 D 等於 validation 的 0.009452，noncentral-t 對 CI_lo>0.005 的條件功效約 96.1%；此估計可能受 validation 選取影響，不是成功保證。樣本量不依新 holdout 結果調整。

## 次要結果與結論界線

- 三個 run 各報 G、D 的名目 95% CI；另對三個 D 報 Bonferroni 同時 95% CI（各用 t(63,1−0.05/6)）。以同時 CI_lo>0 的數量描述固定 checkpoints 的跨 run 一致性，不更換主 run 或主判準。
- 報告 honest、手寫與三個 RL 的系統 regret、各 agent 不合格比例，僅描述，不新增顯著性主張。
- 本實驗確認固定策略對固定手寫基準的差；不宣稱勝過所有手寫方法、不證明最強攻擊、不修復 S1 的漏洞標定混淆，也不證明重新訓練的成功率。
- 完成後可結束「固定 M3C 上存在額外私利」的確認工作。E1 防守方訓練／修補效果另立問題、資料及協定，不自動開始。

## 工程凍結與執行

1. 在學校 CPU 產生 `results/direction2/holdout/manifest.json` 與 `seed_audit.json`，記錄完整 seeds、checkpoint SHA、政策、設定、協定／入口／數值程式雜湊、原選取紀錄及須保持不變的檔案雜湊。兩者提交並同步後才能評估。
2. 先做合成資料驗收：配對統計／門檻邊界、seed stream 碰撞、輸出維度與有限值、快取竄改、已開始／完成工作的防重跑。GPU 短驗收只用訓練 seeds，檢查原 MLP graph/eager 與兩種 honest 路徑一致。
3. 學校單一 GPU 程序、tmux 背景執行。RL 批次用已驗證 graph；honest＋手寫批次用 eager；兩批用相同 64 seeds 並核對 honest 快照。沒有在正式 seeds 上新增 smoke test。
4. 每批進入前寫入 started ledger；原子保存 raw，再寫 completed。已存 raw 僅重建統計，不再模擬；started 卻沒有 raw 時停止並揭露技術中斷，不靜默重跑。每批資料保存後備份 GitHub。這是技術故障停止，不是依效果大小停跑。
5. 全部完成後，以另外一份 CPU 報告程式從 raw 重算 CI、判定、系統統計並核對雜湊；取回本機、保存結果、同步三處版本。原正式 test ledger 應維持 42 筆。

執行：`scripts/d2_holdout_launch.sh`。學校計算估計 5–10 分鐘；含實作、凍結與核對，啟動工作起估計 30–45 分鐘，若有技術故障則回報原因與新時程。
