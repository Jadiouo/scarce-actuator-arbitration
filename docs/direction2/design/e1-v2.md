## 1. 研究問題與判準

**研究問題。** 在固定 M3C、r=0.5、p=0.1、float64、公開資訊 55 參數攻擊模型下，能否以學到的防守設定（h、κ_ref、L），在不惡化誠實使用者服務的前提下，降低「各防守下最強攻擊者」的增益。

**唯一主要判準。** 在全新 test seeds（n=1024）上，「原設定最強攻擊者的 G」減「最終候選最強攻擊者的 G」之逐 seed 配對差 D_s，單側 95% 下界 LB > δ=0.005，**且**誠實 regret 差與不合格比例差的單側 95% 上界各自 ≤ 上限（0.002、0.01）；兩者皆過才稱「修補成立」。判定順序見 §5 決策樹。

**次要結果（只描述，不參與判定，不得在主判定失敗時改用）。**
1. D>0 的單側 95% 下界：即同一個 LB 與 0 比較（LB>0 與否），不另做檢定。
2. 最強攻擊者的殘餘 G 及其 95% CI（對 0 的距離，不等於「已修補完」）。
3. 其餘 11 個攻擊者（3 frozen＋9 再適應中除去 a\*）在 test 上的逐攻擊者配對差，事後描述、未校正多重比較。
4. 誠實成本的逐 agent 結果與完整效用快照。
5. 轉移矩陣：對 C1 適應的攻擊者放到 C2／原設定的 G。
6. 固定手寫池（36 個）在 test 上的最大 G，僅對照。
7. 搜尋邊界貼邊（L 上限 5000）的描述；攻擊飽和旗標（§4）。

## 2. 誠實服務約束（改以 CI 判定）

逐 seed 配對（同 seeds、同記分窗 T_score=T−5000，與原設定比）：ΔR_s＝regret（`metrics()['regret']`，即 `reg_b[0]/T_score`）之差，Δα_s＝不合格比例（`metrics()['alpha']`）之差，皆為「候選−原設定」。單側 95% 上界 UB＝mean(Δ)＋t_{0.95,n−1}·SD(Δ)/√n（t 分布，df＝n−1）。

- **上限（選模與 test 共用同一組）：** ΔR ≤ 0.002、Δα ≤ 0.01，沿用 v1（v1設計「尺與否證條件」；v1結果 §4），與 v1 同尺才能比較；不放寬，因放寬等於接受服務變差。v1 pooled 點估計 +0.00179、+0.00653，CI 上界 0.0033／0.0118 超線（v1結果 §4；逐 seed SD：regret 0.00420、alpha 0.01460，由 sel 的 raw 經 `metrics()` 重算）。
- **為何選模邊際由 0.8 改為 1.0（本版修訂）：** 原草案選模用 0.8×上限（0.0016／0.008）。紅方以 SD ΔR 0.00420、Δα 0.01460 重算：n=128 時 0.8 邊際下，真實 ΔR=+0.00179（v1 pooled 的點估計）的通過機率僅 1.6%（重算，nct），v1 最有效的候選幾乎必被刷掉。test 只評一個候選，選擇偏誤（贏家詛咒）由全新 test seeds 吸收，所以選模不需再加邊際。
- **防守選模（DS seeds，n=128，t=1.6569）：** 可行＝UB_DS(ΔR) ≤ 0.002 且 UB_DS(Δα) ≤ 0.01。以 v1 的 SD 估計，這相當於 DS 點估計 ΔR ≤ 0.00138、Δα ≤ 0.00786（0.002−1.6569×0.0042/√128；0.01−1.6569×0.0146/√128，重算；實際判定用當次樣本的 SD，非此近似）。v1 pooled 水準（+0.00179、+0.00653）在 DS 的通過機率 ΔR 14.0%、Δα 84.8%，聯合約 11.8%（假設兩項獨立，重算；推論）。可行域仍窄，是誠實的限制。
- **最終確認（test，n=1024，t=1.6463）：** 同一上限，UB_test ≤ 上限；兩項各自單側 95%，採交集（兩項都要過）。
- **test 上誠實約束需要的點估計與過關機率（以 v1 SD 0.0042／0.0146，重算；SD 實際未知，推論）：** t·SD/√1024 為 ΔR 0.000216、Δα 0.00075，所以過關須 ΔR 點估計 ≤ 0.00178、Δα ≤ 0.00925。

| 真實 ΔR | 0 | 0.0005 | 0.0010 | 0.0015 | 0.00179 | 0.0020 |
|---|---|---|---|---|---|---|
| 過關機率 | 100% | 100% | 100% | 98.5% | 48.2% | 5.0% |

| 真實 Δα | 0.003 | 0.005 | 0.0065 | 0.008 | 0.009 | 0.010 |
|---|---|---|---|---|---|---|

## 3. Seeds 分割

既有（來源：spec REQ-SEED-01／08／REQ-ENV-21；holdout設計；v1設計）：train 0–999、重播 1000–1031、val 2000–2031、val2 3000–3031、test 5000–5031、holdout 41000000–41000063、E1 pilot 61000000–61000031。generator 實際 seeds＝`s+{0,10^6,2·10^6}`（`scripts/d2_holdout_eval.py::OFFSETS`），歷史流保守再加 `+3·10^6`（`require_disjoint`）；本版新 seeds 也一律展開 `+{0,1,2,3}·10^6` 檢查。

**修訂原因（BLOCKER）：** 原草案 62000000 起的 base 展開 `+10^6` 後落在 63000000 起，且 `+0` 的 62000000 系列與 pilot 61000000–61000031 加 `+10^6`＝62000000–62000031 直接重疊（重算可見）。全部改用 72000000 起的新 base。

| 用途 | 範圍（base seeds） | 數量 | 備註 |
|---|---|---|---|
| 防守訓練 DT | 72000000–72000255 | 256 | CMA-ES 候選間 CRN；每代取 16 個，輪替 |
| 防守選模 DS | 72100000–72100127 | 128 | 只用於可行性 CI 與候選排序 |
| 攻擊者訓練 AT | 72200000–72200255 | 256 | 每代 32 個，輪替 |
| 攻擊者選取 AS | 72300000–72300127 | 128 | checkpoint 選取、飽和判斷、最強攻擊者選取、候選比較 |
| 最終 test | 72400000–72401023 | 1024 | 只在凍結後用一次 |

**互斥檢查（2026-10-15 已用 python 實際驗證，結果：通過）：** 新五塊各展開 `+{0,1,2,3}·10^6`，共 (256+128+256+128+1024)×4＝7168 個整數，集合大小 7168（塊內無重複）；五塊兩兩交集皆為空；與既有七範圍各展開同樣四個偏移（共 4896 個整數，範圍 0–64000031）交集為空。新集合最小 72000000、最大 75401023，既有展開最大 64000031，兩者之間有 ≥8×10^6 的間隔。**推論：** 只能證明本專案保存紀錄無重疊，不能證明沒有未保存的外部執行（同 holdout設計）。

**manifest 寫入並由程式檢查：** (1) 五塊完整 seeds 列表與四偏移展開；(2) 兩兩交集為空、與既有七範圍（含四偏移展開）交集為空，並重現上列計數 7168／4896／0 交集（沿用 `require_disjoint` 並擴充，讀入 pilot／holdout 的 manifest）；(3) 掃描 `results/` 與 checkpoint 的整數 seed 欄位並記來源雜湊；(4) 每個階段入口只接受自己那塊；(5) test 階段在 `selection_frozen.json` 的雜湊寫入 manifest 之前一律拒絕。

**限制：** 新攻擊者 warm start 自三個 frozen checkpoint，後者曾在 train 0–999 訓練（spec REQ-SEED-04），v1 同；AT 與「權重歷史」不是完全無交集，只是不再重用 0–999 作新階段的環境 seeds。

## 4. 攻擊者再適應的公平性與飽和規則

- **統一協定（對原設定、C1、C2 完全相同）：** warm start 自 frozen run0／run1／run2 各一條（3 個 optimizer seeds；對各防守相同）；sep-CMA-ES、σ=0.15、λ=64、n_S=32、**240 代**（v1 為 120 代；v1結果 §4 顯示 pooled 下 G_val 仍在升：0.0194→0.0276，原設定下 120 代內無上升趨勢）；每 20 代（第 0、20、…、240 代）在 AS 驗證 optimizer mean，AS 選 checkpoint。訓練環境 seeds 只用 AT。起始預算（λ、n_S、optimizer seeds、驗證頻率、AT／AS）對三防守逐項相同，寫入 manifest 並在 test 前比對；延長（下述）是唯一允許的預算差異，且由同一規則觸發。
- **G 軌跡（逐代記錄）：** 每條攻擊者鏈記錄每次驗證點的 AS 平均 paired G（optimizer mean；含第 0 代），寫入 raw。軌跡本身是主要診斷，不事後調整。
- **飽和規則（寫死）：** 設某條鏈驗證點為 g=0,20,…,240。「前 200 代最佳」＝g∈[0,200] 的最大 G；「最後 40 代最佳」＝g∈{220,240} 的最大 G。增益＝後者減前者。**增益 < 0.001 才算該鏈飽和**（0.001 約為 AS 平均 SE 0.0012 的量級，推論：0.0135/√128）。
- **延長（寫死，一次）：** 某防守三條鏈中任一條未飽和，則該防守的三條鏈全部續跑 240 代（接續同一 optimizer 狀態，代數 241–480，驗證頻率不變，AS 選 checkpoint 改在全部驗證點上取）。延長後以同一規則重判，「前 440 代最佳」對「g∈{460,480}」，門檻同 0.001。原設定與候選（C1、C2）適用同一規則，不得只延長其中一邊而不依規則。延長後仍有鏈未飽和者，結果中標示「攻擊可能未飽和」，**不改判定規則、不再延長**。飽和判斷與延長由 AS 資料決定，不使用 test。
- **warm-start 不對稱（限制）：** 三個 frozen 起點是針對原設定訓練的，對原設定已是「近最佳回應」，對 C1／C2 則需要重新適應；同樣 240 代對候選防守可能偏不利於攻擊者（候選看起來更安全是被低估攻擊的風險）。飽和規則與延長用來減輕，不能消除；此為列入 §11 的限制。
- **轉移攻擊者：** 每個防守的適應攻擊者與 3 個 frozen 放到其他防守的 AS 上評估（無訓練），全部納入候選。每個防守候選攻擊者集合＝3 frozen＋9 適應＝12 個。
- **最強攻擊者 a\*_X：** 對每個防守 X，在 AS 上取 12 個中平均 G 最大者（平手取清單序：frozen run0..2，再依防守順序原設定、C1、C2）。a\* 在 AS 上定案後寫入 `selection_frozen.json`，**test 主判定只評這個固定攻擊者**，沒有 argmax 的上偏（v1 的最大值在同批 seeds 上取，v1結果 §3）。
- **多輪：** 見 §7 的 Round 2；仍不宣稱收斂。

## 5. 主要判定規則（決策樹）

估計量：D_s＝G_orig(a\*_orig; s) − G_C\*(a\*_C\*; s)，s 為 test 的 1024 個 seeds。LB＝mean(D)−t_{0.95,1023}·SD(D)/√1024（**單側 95%，t 分布 df=1023，t=1.6463**，重算）。UB_D＝mean(D)+同一 t·SD/√1024（單側 95% 上界）。誠實兩項的 UB 亦為單側 95%、df=1023。所有 CI 均為單側；本文不報雙側 CI 作為判定依據。

**δ＝0.005 的來源與意義：** 沿用 holdout設計的效應尺度與 v1 的 0.005 門檻（v1設計；conclusion 的 holdout 登記同值），視為「實質效果」門檻，不是統計顯著門檻。v1 pooled 的最強攻擊者配對差為 0.0086 [0.0047,0.0125]（v1結果 §3，pooled_adapt0）；原設定最大 G 為 0.0363，δ 約為其 14%（0.005/0.0363，推論）。不取更高值：v1 的半樣本在 0.0034–0.0099 間擺動（v1結果 §4）。D>0 的單側 CI 只作次要結果。

**決策樹（依序判斷，第一個命中的節點即為結果）：**
1. 選模階段沒有候選進 test（§7）→ **「未進 test：無候選滿足誠實約束」**（或「未進 test：無可行候選達到 AS 改善」，見 §7）。不使用 test seeds，結束。
2. 令 H＝（UB_test(ΔR) ≤ 0.002 且 UB_test(Δα) ≤ 0.01），E＝（LB > 0.005）。
3. H 且 E → **成立**：「在 M3C、r=0.5 與本攻擊者預算下，最終候選相對原設定降低最強已知攻擊者的增益超過 0.005，且未超出誠實服務上限。」不得說「通用修補」。
4. 非 H 且 E → **誠實越線**：「攻擊增益下降，但誠實服務代價超出預登記上限；不構成修補。」報超出多少。
5. 非 H 且非 E → **兩者皆失敗**：「此候選既未確認降低攻擊增益，也未確認服務維持；不採用。」
6. H 且非 E → **效果不足**，子標籤依序判斷、命中即止：(a) 若 UB_D < 0.005 → 「排除達到 0.005 的降幅」；(b) 否則若 LB > 0 → 「有降幅但未確認超過 0.005」；(c) 否則 → 「證據不足以判定」。(a) 與 LB>0 可同時成立（例：D 的單側區間在 0 與 0.005 之間），此時標籤取 (a)，LB>0 與否另列一行事實，不改標籤。

嚴格不等號；LB 恰等於 δ 不算 E。結果出來後不改 δ、上限、a\*、候選或 seeds 數；攻擊「可能未飽和」旗標只加註，不改節點。

## 6. 檢定力（test seeds 數 n=1024）

公式（單側、非中心 t，與 holdout設計同法）：power(n)＝P[T_{n−1}(λ) > t_{0.95,n−1}]，λ＝(μ−δ)/(σ_D/√n)，δ=0.005。

- **σ_D 來源：** cv `rows[original/pooled].learned_G_per_seed`（9 攻擊者×32 seeds），逐攻擊者 D＝G_orig−G_pooled 的 SD(ddof=1)：0.0108（pooled_adapt0）至 0.0150（pooled_adapt1），9 個平均 0.0130（以 cv 重算）；最強 vs 最強的配對差 SD＝0.01082、均值 0.00861。規劃用 σ_D＝0.0135 與 0.015 兩種（後者為 v1 觀察到的最大值；v1 只有 32 seeds，SD 估計本身有不確定性，推論）。
- **檢定力表（n=1024，重算；括號為原草案 n=288 供對照）：**

| μ（真實平均降幅） | σ_D=0.0135 | σ_D=0.015 |
|---|---|---|
| 0.005（＝δ，等於型一錯誤） | 5.0%（5.0%） | 5.0%（5.0%） |
| 0.006 | 76.5%（34.8%） | 68.7%（30.3%） |
| 0.007 | 99.9%（80.6%） | 99.6%（73.0%） |
| 0.008 | 100%（98.3%） | 100%（95.9%） |

- n=1024 時 power≥0.80 的最小真實 μ：σ_D=0.0135 為 0.00605、σ_D=0.015 為 0.00617（重算）。μ<0.006 時檢定力迅速掉到 <70%，這是 δ 近 0.005 下的固有限制：真實降幅略超 δ（例 0.0055）時多半判不出來，只是「效果不足」，不是「無效」。
- **n 的調整：** 原草案 n=288 在 μ=0.007 才 80.6%、μ=0.006 僅 34.8%；紅方認為偏低。改 n=1024（=32×32），固定，不依後續結果調整。μ=0.007 所需最小 n：σ_D=0.0135 為 284、0.015 為 350；μ=0.006 則需 1129／1393（重算），故 n=1024 對 μ=0.006 約 77%／69%，不全達 0.80，這是接受的取捨。
- 誠實約束的過關機率見 §2 兩張表（n=1024）。
- DS 的 n=128 只決定可行性，不保證 test 通過；AS 的 n=128 用於選擇，其 SD/√128 約 0.0012（0.0135/√128），足以辨認相差 ≥0.004 的攻擊者（推論）。

## 7. 候選數、選取規則與多重比較

- **進 test 的候選數固定為 1（對上原設定）。** 不用 Bonferroni，因只有一個主檢定。
- **候選生成（全在 test 之外）：**
  - Round 1 防守訓練：pooled 目標（36 手寫＋3 frozen；v1 的 hw 目標無效果，捨棄，v1結果 §4），2 條 optimizer seeds，λ=8、12 代，從原設定起始，DT 訓練；每 4 代（gen 4、8、12）在 DS 做 CI 可行性（§2）與 worst G，各 run 取可行者中 worst G 最小者，兩 run 的結果再取 worst G 較小者，得 **C1**。若兩 run 都沒有任何可行 checkpoint，則無 C1，不做 Round 2，直接走下方「無可行候選」。
  - 對原設定與 C1 做統一協定攻擊（§4）；Round 2：把 C1 下 AS 選出的 3 個適應攻擊者加入訓練池，從 C1 起始再訓 2 條，同法選出 **C2**（若無可行 checkpoint，C2＝C1）。再對 C2 做統一協定攻擊（C2＝C1 時省略）。
- **選取規則（寫死）：** 候選集 {C1, C2}（C2＝C1 時只有一個）。先限 DS 可行者。在可行者中，以各防守的 G(a\*_X)（AS 上 12 個攻擊者中的最大平均 G，§4）比較，**最小者為 C\***。平手（差 < 10^-9）取 C1。
- **「G 優於原設定」的具體定義：** AS 上 G(a\*_orig) − G(a\*_C\*) > 0（嚴格大於零，不設門檻；實質門檻 δ 只在 test 判定使用）。若 C\* 不滿足，視為無候選進 test。
- **無候選進 test 的措辭：** (i) 無任何可行候選 → 「未進 test：無候選滿足誠實約束」；(ii) 有可行候選但 AS 上無一優於原設定 → 「未進 test：無可行候選達到 AS 改善」。兩種情況都不使用 test seeds（不消耗）、不開 test 階段，仍報 AS／DS 資料與攻擊軌跡。這是有效結果，不得重跑或改搜尋空間。
- 比較只在 AS 上進行，選擇偏誤由 test 的新 seeds 吸收。
- v1 觀察到 L 貼邊（hw L=5000；v1結果 §4），搜尋範圍沿用 v1（h∈[4,8]、κ_ref∈[0.35,0.65]、L∈[1000,5000]，v1設計），不擴大。若 C\* 的 L 貼上界，報告註明，不宣稱最佳。

## 10. 預期結果與風險（登記時的估計）

坦白寫在結果前：v1 **沒有**觀察到同時滿足「誠實代價低」與「G 降幅 ≥ 0.007」的候選。
- hw 候選：誠實代價為負（sel 的選模 ΔR＝−0.00393，即服務更好），但最強攻擊者 G 降幅僅 0.0006（v1結果 §3–4）。
- pooled 候選：降幅 0.0086 [0.0047,0.0125]（v1結果 §3），但誠實代價為 ΔR +0.00179、Δα +0.00653，CI 上界超線（v1結果 §4）。
- 此二者是兩個不同候選，沒有一個候選兼具兩者；本版只是希望 Round 1／Round 2 的搜尋（含 pooled 目標與共同進化）找到兼具者，這是推論性的期望，無數據保證。
- 以 §2 與 §6 的表為準，若候選落在 pooled 水準（ΔR +0.0018），test 誠實過關機率約 48%；若降幅 0.006，power 約 69–77%。粗估（推論）：「成立」不是預設結果。可能結果包括「效果不足」（降幅不夠或誠實過但 LB≤δ）與「未進 test：無候選滿足誠實約束」。
- **這些非成立結果也有研究價值：** 它們量化「修補攻擊增益」與「維持誠實使用者服務」之間的取捨（Pareto 前緣），並說明在固定攻擊者預算下，單靠調 h、κ_ref、L 是否足以修補。登記時承諾：不論結果為何都完整報告，不以事後更換候選、δ 或上限來追求「成立」。

## 11. 不能宣稱的事與和主實驗結論的關係

不能宣稱：Nash 或收斂（只有兩輪 defender→attacker）；最強攻擊（只是「已知 12 個攻擊者中最強」；v1 在原設定下 120 代未找到更強攻擊，不知是已飽和或 warm-start 不足，v1結果 §4；本版以飽和規則減輕但不排除，warm-start 對原設定與候選不對稱，見 §4）；通用修補（限 M3C、r=0.5、p=0.1、公開資訊模型、此 h／κ_ref／L 範圍）；S1 已重新標定或「改機制後 planted-exploit 檢測力」（仍未檢驗，v1設計；殘餘 G 低也可能是攻擊者池不足）；誠實使用者「無代價」（只確認 CI 上界在上限內，非等效）；跨機制、真實機器人、重新訓練成功率；與舊 97500 記分窗的絕對值互比（記分窗為 T−5000）。「成立」也不代表殘餘 G 為零。

**與主實驗結論的關係。** 主結論（D=+0.010778 [+0.007362,+0.014194]，64 seeds，`docs/direction2/results/conclusion.md`）是「原設定下學習策略有額外私利」，本設計不改它；E1 v2 回答另一個問題（修補是否有效）。若「成立」，正確說法是「在此攻擊者池下，修補後最強已知攻擊者的增益降低」，並不否定原結論；若不成立，主結論不受影響。S1 的檢測力限制與 D2／O5 的混淆（conclusion）不因本設計而解除。本設計的 DS／AS／test 是新資料，v1 的 validation 61000000–61000031 與 holdout 41000000–41000063 都不再用於選模或確認。
