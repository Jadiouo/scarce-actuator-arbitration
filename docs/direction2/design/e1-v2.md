# E1 第二版：可確認的防守修補設計（預先登記草案；2026-10-15）

只寫設計，不實作、不跑 GPU。凍結前仍可修改；凍結（commit＋manifest 雜湊）後才能碰任何新 seeds。來源簡寫：v1設計＝`docs/direction2/design/e1-pilot.md`；v1結果＝`docs/direction2/results/e1-pilot.md`；cv＝`results/direction2/e1_pilot/cross_validation.json`；sel＝`.../selection.json`；pre＝`.../preflight.json`；st＝`.../status.json`；holdout設計＝`docs/direction2/design/independent-holdout.md`；spec＝`docs/direction2-spec.md`。「推論」＝由數字推得、未直接量測。

## 1. 研究問題與判準

**研究問題。** 在固定 M3C、r=0.5、p=0.1、float64、公開資訊 55 參數攻擊模型下，能否以學到的防守設定（h、κ_ref、L），在不惡化誠實使用者服務的前提下，降低「各防守下最強攻擊者」的增益。

**唯一主要判準（一句話）。** 在全新 test seeds 上，「原設定最強攻擊者的 G」減「最終候選防守最強攻擊者的 G」之逐 seed 配對差，單側 95% 下界 > δ=0.005，**且**誠實 regret 差與不合格比例差的單側 95% 上界各自 ≤ 上限（0.002、0.01）；兩者皆過才稱「修補成立」。

**次要判準（只描述，不參與判定，不得在主判定失敗時改用）。**
1. 最強攻擊者的殘餘 G 及其 95% CI（對 0 的距離，不等於「已修補完」）。
2. 其餘 11 個攻擊者（3 frozen＋9 再適應中除去 a\*）在 test 上的逐攻擊者配對差，標明是事後描述、未校正多重比較。
3. 誠實成本的逐 agent 結果與完整效用快照。
4. 轉移矩陣：對 C1 適應的攻擊者放到 C2／原設定的 G。
5. 固定手寫池（36 個）在 test 上的最大 G，僅對照。
6. 搜尋邊界貼邊（L 上限 5000）的描述。

## 2. 誠實服務約束（改以 CI 判定）

逐 seed 配對（同 seeds、同記分窗 T_score=T−5000，與原設定比）：ΔR_s＝regret（`metrics()['regret']`，即 `reg_b[0]/T_score`）之差，Δα_s＝不合格比例（`metrics()['alpha']`）之差，皆為「候選−原設定」。單側 95% 上界 UB＝mean(Δ)＋t_{0.95,n−1}·SD(Δ)/√n。

- **上限沿用 v1：** ΔR ≤ 0.002、Δα ≤ 0.01（v1設計「尺與否證條件」；v1結果 §4）。理由：(i) 與 v1 同尺才能比較；(ii) v1 pooled 的點估計為 +0.00179、+0.00653，CI 上界 0.0033／0.0118 超線（v1結果 §4，逐 seed SD：regret 0.00420、alpha 0.01460，由 sel 的 raw 經 `metrics()` 重算）。不放寬上限，因放寬等於接受服務變差。代價是可行域縮小；v1 的 hw_run0/gen9 之類 regret +0.0022 的候選即不可行（v1結果 §4），更低 G 的區域可能全在線外，這是誠實的結果。
- **防守選模（DS seeds，n=128）：** 候選須 UB_DS(ΔR) ≤ 0.8×0.002＝0.0016 且 UB_DS(Δα) ≤ 0.8×0.01＝0.008 才算可行。0.8 的安全邊際是為抵銷「在選模 seeds 上挑到僥倖低值」的贏家詛咒（推論；比例 0.8 為設計選擇，無實測依據）。n=128 時 regret 的 t·SD/√n≈1.657×0.0045/√128≈0.00066，所以真實 ΔR 約 ≤0.0009 的候選才有機會通過。
- **最終確認（test，n=288）：** UB_test ≤ 上限（0.002／0.01，無邊際）。兩項各自 95% 單側，採交集檢定（兩項都要過），不需再對這兩項做多重校正。
- 不可行候選不得進入 test；若無可行且 G 優於原設定的候選，記「搜尋未產生可用候選」，不開 test（test seeds 不消耗）。

## 3. Seeds 分割

既有（來源：spec REQ-SEED-01／08／REQ-ENV-21；holdout設計；v1設計）：train 0–999、重播 1000–1031、val 2000–2031、val2 3000–3031、test 5000–5031、holdout 41000000–41000063、E1 pilot 61000000–61000031。generator 實際 seeds＝`s+{0,10^6,2·10^6}`（`scripts/d2_holdout_eval.py::OFFSETS`），歷史四流保守再加 `+3·10^6`（`require_disjoint`）。

| 用途 | 範圍（base seeds） | 數量 | 備註 |
|---|---|---|---|
| 防守訓練 DT | 62000000–62000255 | 256 | CMA-ES 候選間 CRN；每代取 16 個，輪替 |
| 防守選模 DS | 62100000–62100127 | 128 | 只用於可行性 CI 與候選排序 |
| 攻擊者訓練 AT | 62200000–62200255 | 256 | 每代 32 個，輪替 |
| 攻擊者選取 AS | 62300000–62300127 | 128 | checkpoint 選取、最強攻擊者選取、候選防守比較 |
| 最終 test | 62400000–62400287 | 288 | 只在凍結後用一次 |

每塊 base 範圍與其 `+0／+10^6／+2·10^6／+3·10^6` 展開集合，彼此之間及與上列 7 個既有範圍的展開集合皆互斥。各塊相隔 10^5 以上，且最大 base 62400287＜63000000，不撞 61000000 系列。**推論：** 只能證明本專案保存紀錄無重疊，不能證明沒有未保存的外部執行（同 holdout設計）。

**manifest 寫入並由程式檢查：** (1) 五塊完整 seeds 列表與展開；(2) 兩兩交集為空、與既有七範圍交集為空（沿用 `require_disjoint`，再加對 pilot／holdout 的 manifest 讀入）；(3) 掃描 `results/` 與 checkpoint 的整數 seed 欄位（同 holdout 作法）並記來源雜湊；(4) 每個階段入口只接受自己那塊（`require_seeds(sd,stage,m)` 以 stage 對應集合，其他階段傳入一律拋錯）；(5) test 階段在 `selection_frozen.json` 的雜湊寫入 manifest 之前一律拒絕。

**限制：** 新攻擊者 warm start 自三個 frozen checkpoint，後者曾在 train 0–999 訓練（spec REQ-SEED-04），v1 同；故 AT 與「權重歷史」不是完全無交集，只是不再重用 0–999 作新階段的環境 seeds。

## 4. 攻擊者再適應的公平性

- **統一協定（對原設定、C1、C2 完全相同）：** warm start 自 frozen run0／run1／run2 各一條（3 個 optimizer seeds，≥3；optimizer seeds 對各防守相同）；sep-CMA-ES、σ=0.15、λ=64、n_S=32、**240 代**（v1 為 120 代，v1結果 §4 顯示 pooled 下 G_val 仍在升：0.0194→0.0276，故延長；原設定下 120 代內無上升趨勢）；每 20 代在 AS 驗證 optimizer mean，含初始模型，AS 選 checkpoint。訓練環境 seeds 只用 AT。
- 預算（代數、λ、n_S、optimizer seeds 數、驗證頻率、AT／AS）對三個防守逐項相同，寫入 manifest 並在 test 前比對。每個防守 3 條，合計 9 條。
- **轉移攻擊者：** 另把每個防守的適應攻擊者與 3 個 frozen 放到其他防守的 AS 上評估（無訓練，成本低），全部納入「最強攻擊者」候選。故每個防守的候選攻擊者集合＝3 frozen＋9 適應＝12 個。
- **最強攻擊者 a\*_X：** 對每個防守 X，在 AS 上取 12 個中平均 G 最大者。a\* 的身分在 AS 上定案後寫入 `selection_frozen.json`，**test 只評這個固定攻擊者**，所以 test 上沒有 argmax 的上偏。（v1 的最大值在同批 seeds 上取，有贏家詛咒，v1結果 §3。）
- **多輪（解決「只再適應一輪」）：** 見 §7 的 Round 2：防守方在第一輪攻擊者加入訓練池後重新最佳回應，再以統一協定攻擊。仍不宣稱收斂。

## 5. 主要判定規則

估計量：D_s＝G_orig(a\*_orig; s) − G_C(a\*_C; s)，s 為 test 的 288 個 seeds；G 為各自防守下以「同防守 honest 效用」為基準的 paired G（v1設計「尺與否證條件」）。LB＝mean(D)−t_{0.95,287}·SD(D)/√288（t＝1.6502，由 scipy 計算）。

- **δ＝0.005 每輪個人效用差：** 沿用 holdout設計的 δ 與 v1 的 0.005 門檻（v1設計；conclusion 的 holdout 登記同值）。v1 pooled 的最強攻擊者配對差為 0.0086 [0.0047,0.0125]（v1結果 §3，pooled_adapt0）；原設定最大 G 為 0.0363，故 δ 約為其 14%（推論，算式 0.005/0.0363）。不取更高值：v1 的半樣本在 0.0034–0.0099 間擺動（v1結果 §4）。

| 結果 | 條件 | 措辭 |
|---|---|---|
| **成立** | LB>δ 且誠實兩項 UB 皆在上限內 | 「在 M3C、r=0.5 與本攻擊者預算下，最終候選相對原設定降低最強已知攻擊者的增益超過 0.005，且未超出誠實服務上限。」不得說「通用修補」。 |
| **效果不足** | 誠實過；LB≤δ | 若 LB>0：「有降幅但未確認超過 0.005」。若 UB_D<δ：「排除達到 0.005 的降幅」。其餘：「證據不足以判定」。 |
| **誠實越線** | LB>δ；任一誠實 UB 超上限 | 「攻擊增益下降，但誠實使用者服務代價超出預登記上限；不構成修補。」報超出多少。 |
| **兩者皆失敗** | LB≤δ 且誠實越線 | 「此候選既未確認降低攻擊增益，也未確認服務維持；不採用。」 |
| **未進 test** | 選模階段無可行候選 | 「本搜尋空間內，在誠實約束 CI 下未找到優於原設定的候選。」test seeds 未消耗。 |

嚴格不等號；LB 恰等於 δ 不算成立。結果出來後不改 δ、上限、a\*、候選或 seeds 數。

## 6. 檢定力（test seeds 數）

公式（單側、非中心 t，與 holdout設計同法）：power(n)＝P[T_{n−1}(λ) > t_{0.95,n−1}]，λ＝(μ−δ)/(σ_D/√n)。解 power≥0.80 的最小 n。

- **σ_D 來源：** cv `rows[original/pooled].learned_G_per_seed`（9 攻擊者×32 seeds），逐攻擊者 D＝G_orig−G_pooled 的 SD(ddof=1)：0.0108（pooled_adapt0）至 0.0150（pooled_adapt1），9 個平均 0.0130（以 cv 重算）；最強 vs 最強（各自取均值 argmax）的配對差 SD＝0.01082、均值 0.00861。規劃取 σ_D＝**0.0135**（9 個平均上取整，偏保守；v1 只有 32 seeds，SD 估計本身有不確定性，推論）。
- **規劃真效應 μ：** v1 的 0.0086 有贏家詛咒與 in-sample 成分（v1結果 §4），打折到 **0.0070**（約 19% 折扣，數值為設計選擇）。
- 結果（本文以 scipy `nct` 計算）：σ_D＝0.0135、μ＝0.0070 時，n＝256 為 76.4%，**n＝288 為 80.6%**；σ_D＝0.0108 時 n＝288 為 93.2%；σ_D＝0.015 時為 73.0%；μ＝0.0086 時皆 ≥99%；μ＝0.0060 時僅 34.8%（σ_D＝0.0135）。固定 **n_test＝288**（9×32），不依後續結果調整。
- 誠實約束的檢定力：n＝288 時 t·SD/√n：regret≈1.650×0.0045/√288≈0.00044、alpha≈1.650×0.0162/√288≈0.00158（SD 取 hw／pooled 的 0.0042–0.0049、0.0146–0.0162，來源同 §2）。若最終候選真實 ΔR≤0.0010、Δα≤0.0075，各項通過機率約 ≥99%（推論，常態近似：ΔR 的 z≈(0.002−0.0010)/(0.0045/√288)−1.65≈2.2 起算，粗估偏高處未扣 SD 估計誤差）。
- DS 的 n＝128 只決定可行性，不保證 test 通過；AS 的 n＝128 用於選擇，其 SD/√128 約 0.0012（0.0135/√128），足以辨認相差 ≥0.004 的攻擊者（推論）。

## 7. 候選數與多重比較

- **最多 1 個最終候選進 test（對上原設定）。** 不用 Bonferroni，因只有一個主檢定；用掉 Bonferroni（α/2）會使 n 約增 27%（推論，由 z 分數比 (1.96+0.84)²/(1.645+0.84)² 估）。
- **候選生成（全在 test 之外）：**
  - Round 1 防守訓練：pooled 目標（36 手寫＋3 frozen；v1 的 hw 目標無效果，捨棄，v1結果 §4），2 條 optimizer seeds，λ=8、12 代，從原設定起始，DT 訓練；每 4 代（gen 4、8、12）在 DS 做 CI 可行性與 worst G，各 run 取可行者中 worst G 最小者，得 **C1**。
  - 原設定攻擊（統一協定）及 C1 攻擊；Round 2：把 C1 下 AS 選出的 3 個適應攻擊者加入訓練池，從 C1 起始再訓 2 條，同法選出 **C2**（若無可行且更好者，C2＝C1）。再對 C2 做統一協定攻擊。
  - 比較 {C1,C2}：兩者在 AS 上的 G(a\*) 較小且在 DS 可行者勝出，得唯一最終候選 C\*。兩者只在 AS 上比，贏家詛咒由 test 的新 seeds 吸收。
- v1 觀察到 L 貼邊（hw L=5000；v1結果 §4），搜尋範圍沿用 v1（h∈[4,8]、κ_ref∈[0.35,0.65]、L∈[1000,5000]，v1設計），不擴大，以免改變問題。若 C\* 的 L 貼上界，報告須註明，不宣稱最佳。

## 10. 不能宣稱的事與和主實驗結論的關係

不能宣稱：Nash 或收斂（只有兩輪 defender→attacker）；最強攻擊（只是「已知 12 個攻擊者中最強」，攻擊端強度有限；v1 在原設定下 120 代未找到更強攻擊，不知是已飽和或 warm-start 不足，v1結果 §4）；通用修補（限 M3C、r=0.5、p=0.1、公開資訊模型、此 h／κ_ref／L 範圍）；S1 已重新標定或「改機制後 planted-exploit 檢測力」（仍未檢驗，v1設計；殘餘 G 低也可能是攻擊者池不足）；誠實使用者「無代價」（只確認 CI 上界在上限內，非等效）；跨機制、真實機器人、重新訓練成功率；與舊 97500 記分窗的絕對值互比（記分窗為 T−5000）。「成立」也不代表殘餘 G 為零。

**與主實驗結論的關係。** 主結論（D=+0.010778 [+0.007362,+0.014194]，64 seeds，`docs/direction2/results/conclusion.md`）是「原設定下學習策略有額外私利」，本設計不改它；E1 v2 回答另一個問題（修補是否有效）。若「成立」，正確說法是「在此攻擊者池下，修補後最強已知攻擊者的增益降低」，並不否定原結論；若「不成立」，主結論不受影響。S1 的檢測力限制與 D2／O5 的混淆（conclusion）不因本設計而解除。本設計的 DS／AS／test 是新資料，v1 的 validation 61000000–61000031 與 holdout 41000000–41000063 都不再用於選模或確認。
