# 方向二：用 RL 訓練的對手（「專業騙子」）——決策紀錄

建立：2026-10-06。使用者指示：
- commander 模式：subagent 一律 sonnet；commander 只負責規劃、派工、審查。
- 先寫 SDD（規格）與 TDD（測試），先寫驗證、再實作。
- 實作前先做三輪紅方／白方攻防，把方向確認清楚。
- GPU 不限量，但一律用 `gpujob` 排隊。
- 模型（抽象模型或環形模擬）由 commander 選擇。

## 初版提案 v0（commander，待第 1 輪攻防）

### 動機
方向一每一輪紅方都指向同一個弱點：結論取決於手寫的說謊策略族。
- oracle 策略主導最大得利。
- 自適應策略實作偏弱。
- F3 的結果是混合的：無資訊策略能拿到多少，取決於策略寫得好不好。

方向二用學習出來的對手取代手寫策略族，檢驗方向一的結論是否成立。

### 研究問題
- **Q1**：RL 對手能不能在 M3C（派遣時 CUSUM）、QM（J-S 邊際配額）、M4（低機率突襲，對象含得標者）上，找到超過最佳手寫策略的得利？
- **Q2**：方向一的主結論「M4 最穩健（G≤0）」在學習型對手下是否仍成立？
- **Q3**：無資訊的學習型對手（看不到對手的當期回報）能拿到 oracle 得利的多少比例？這是 F3 的再檢驗。

### 模型
沿用方向一的抽象重複分配模型（arbitration/gpu/frontier.py、quota.py）：
- K=3，高斯 copula AR(1) 型別，延遲 τ，z 空間 r=ρ^τ。
- 機制參數固定為方向一選定的參數，不針對 RL 重新調參。
- 理由：
  - 結果可以與方向一的短文直接比較。
  - GPU 批次模擬速度快，RL 需要大量 episode。
- 延伸目標：接回環形空間模擬（arbitration/gpu/sim_torch.py）。

### 對手
- 單一偏離者，策略 π(觀察) → 灌水量 d ≥ 0（連續值）。
- 兩種觀察集合：
  - **無資訊**：自己的型別、自己的歷史（是否得標、是否被稽核、懲罰狀態、自估的 CUSUM 統計量），以及公開的時間資訊。
  - **oracle**：再加上對手的當期回報。
- 訓練法候選：
  - Evolution Strategies：適合大批次 GPU，對稀疏、延遲回報較穩。
  - PPO。
  - 由攻防決定用哪一種。
- 其他 agent 誠實。延伸目標：多個學習型偏離者／共謀。

### 指標
- 偏離者相對誠實時的得利 G（paired，95% CI）。
- 與最佳手寫策略比較。
- 訓練與評估使用不同 seeds：訓練用 0–999，評估用 5000–5031。
- 同時報告誠實者被誤罰率與 R/T。

### 事前否證／健全性條件（草案，待攻防後定稿）
- **S1（健全性）**：RL 對手在 NAIVE（直接相信回報）上，必須接近已知最佳得利 0.28。在 M3C 上，至少要達到最佳無資訊手寫策略的水準。做不到代表訓練有問題，應修正訓練，不能拿來主張「機制很穩」。
- **S2**：若 RL 在 M4 上的得利 CI 下界 > 0，即推翻方向一的「M4 最穩健」結論，必須照實更正短文。
- **S3**：任何 RL 得利，都必須在獨立的評估 seeds 上重現。單次訓練的偶然結果不算數。

### 開發流程
1. 三輪攻防，每一輪都派紅方與白方，commander 修訂提案。
2. 定稿 SDD：docs/direction2-spec.md。
3. TDD：先寫測試，並確認它們會失敗。至少包含：
   - 環境與 frontier.simulate 逐 seed 一致。
   - 灌水量為 0 的對手，結果與誠實時逐位元相同。
   - 重播手寫策略，得利與方向一的 JSON 一致。
   - gpujob 的使用規範。
4. 實作，讓測試通過。
5. 執行實驗。
6. 每個階段結束都由紅方攻擊。

## 提案 v2（待第 3 輪攻防）

### 主問題
- **Q-main**：在 M3C（派遣時 CUSUM）上，學習型無資訊對手能否找到最佳手寫無資訊策略找不到的得利？
  - 指標：測試 seeds 上的未截斷 G_RL、G_手寫，以及兩者差值（附 paired 95% CI）。
  - 重點 cell：r=0.9。方向一中，手寫的無資訊得利在這裡約為 0（F3 混合結果的懸案）。對照組為 r=0.5。
- **次要**：
  - oracle 版（用無資訊解暖啟動，策略類別嵌套），解讀為資訊價值的上界。
  - QM。
  - r=0.99。
  以上皆列延伸目標。

### 對手
- **觀察**：機制狀態的手工充分統計量，依 Kerckhoffs 原則對手已知。逐機制列表：
  - M3C：自己的型別 z、CUSUM 值 S、暫停計時器、最近 k 次是否得標、最近 k 次的稽核結果（若可見）。
  - 不給絕對時間。
  - 風險：遺漏的特徵會漏掉依賴更長歷史的漏洞。此限制要明寫。
- **策略**：小型 MLP 或參數化策略族（≤50–200 個參數），直接輸出回報 v∈[0,1]。
- **優化**：CMA-ES（或 ES），以 CRN 配對，目標為無折扣平均報酬。可用手寫策略暖啟動。

### 硬性關卡 S1（檢測力標定）
- **無資訊可找回組**：
  1. NAIVE（約 0.28）。
  2. M4 舊版 rw=0（以 r=0.9 或可行的 r 重新量測已知得利）。
  3. **盲設計的人造漏洞**：由另一個 agent 設計，它看不到特徵設計與策略類別，而且漏洞不在手寫族內。例如 M3C 中「連續乾淨 k 步後 CUSUM 減量」這類需要特定時序才能利用的規則。漏洞大小掃描 {0.003, 0.01, 0.03, 0.1}，畫出檢測力曲線。
- **通過標準**：前兩項找回已知得利的 ≥80%；人造漏洞在 ≥0.03 時找回。實際門檻依 CRN 量測結果定稿於 SDD。
- 之後「沒找到漏洞」的結論，只能寫成「≥x 的漏洞會被找到」。

## 提案 v1（已被 v2 取代）

### 定位
不是新方法，而是在「延遲驗證＋持久型別」的稽核機制上做 **exploitability 評估**，並用 **planted-exploit 標定檢測力**。屬於評估方法學加實證。設定為 Stackelberg：機制先承諾、對手做最佳回應。結論僅限抽象模型。

### 研究問題
- **Q1**：學習型對手在 M3C 與 QM 上的 ε-IC regret（相對誠實的最大得利）。與最佳手寫策略的比較列為次要。
- **Q2'**：M4 改為解析處理。寫出「突襲機率 × 懲罰 ≥ 單次灌水最大得利」的不等式，並把突襲成本 c 當掃描參數做數值驗證。RL 只用來在 M4 上做 planted-exploit 對照（舊版 rw=0）。
- **Q3**：無資訊與 oracle 兩種對手的得利差值，附 CI，不用比值。

### 對手
- **觀察**：每個機制各一張表，寫死欄位。
  - 共同欄位：自己的型別、自己是否得標（並註明這會洩漏對手最大值的資訊）。
  - 不給絕對時間；QM 只給區塊內的位置與自己的剩餘配額。
  - 稽核事件是否可見，依機制如實設定。
  - 依 Kerckhoffs 原則，機制規則與參數對手已知。
  - oracle 版另外可以看到對手的當期回報，作為上界。
- **動作**：直接報出回報 v∈[0,1]；QM 為 bin 的 categorical。
- **策略**：小型 GRU，處理 POMDP。
- **訓練**：ES，搭配共同隨機數與對偶取樣，優化無折扣的平均報酬。可用手寫策略暖啟動或行為複製。不用 PPO。

### Horizon
- 訓練用幾何終止，或「評估時排除最後 L 輪」。
- 觀察不含絕對時間。

### 硬性關卡 S1（planted-exploit 套件）
不通過就停止，並改為報告訓練方法的負面結果。RL 必須在無資訊與 oracle 兩種觀察下，重新找到以下已知漏洞：
1. NAIVE／M2：已知得利約 0.28。
2. M4 舊版 rw=0：r=0.99 時為 0.0356。
3. M3C 在 ρ 低估時：0.0556。
4. M3C 的 edge_oracle：0.087（r=0.5）與 0.0211（r=0.9）。
5. QM 的 savemin_oracle：約 0.09。

報告「可偵測最小得利」，也就是找回已知漏洞的比例。之後任何「沒找到漏洞」的結論，都只能寫成「大於 x 的漏洞會被找到」。

可選：在 K=2 的小例上用 DP 求精確最佳回應，標定 RL 與最優之間的差距。

### Seeds 與統計
- 環境 seeds 分三組：訓練 0–999、驗證 2000–2031（只用來選超參數、選 run、早停）、測試 5000–5031（只用來報數字）。
- 事先登記每個設定的 RL 訓練次數（例如 3 個訓練 seed），全部報告，不只報最好的一次。
- 數字一律由腳本從 JSON 取值並登錄 number-audit。

### 範圍與算力
- 最小版本：抽象模型、單一偏離者、ES＋GRU、M3C 與 QM 各 2 個 r 值（0.8、0.99）、2 種資訊集，加 M4 的解析分析與 planted-exploit 對照。
- 算力：先讓模擬器支援「ES 族群 × seeds」的大批次（族群放進 batch 維度），並優化單步耗時（CUDA graph 或 torch.compile）。訓練用 T=2e4 加幾何終止；評估用 T=1e5。
- 延伸目標：共謀、環形空間子實驗、機制共同演化。
- 時程上限：4 週，分 3 個里程碑。
  - M1：文獻、SDD、TDD、環境對齊。
  - M2：S1 關卡。
  - M3：主實驗加紅方審查。
  - 超過上限就收斂成短文，不開新框架。

### 三種結果事先寫好的說法
- **(i) 找到新漏洞**：先用獨立重寫的環境排除模擬器 bug；在測試 seeds 上重現；描述漏洞的形態；更正方向一的短文。
- **(ii) 只追平手寫策略**：前提是 S1 通過。可以寫成「在檢測力 x 之下，手寫策略族已近似最佳回應；方向一的結論對學習型對手也成立」。
- **(iii) 學不起來**：S1 不通過時，報告訓練方法的負面結果，並退到小型參數化策略加 CMA-ES。不管哪一種結果，「可重複的 RL 紅隊評估框架」本身都是保底產出。
