Who gets the scarce resource when someone may lie?

A scarce server hands one item per round to one of three agents. Each agent reports how urgent its need is, and reporting is free, so one of them may exaggerate. The server can only check a claim later, by which time the truth has already drifted. Honest agents therefore never match their old claims exactly, and a checker must tell drift from lying. Pick a mechanism and a lying strategy, then watch who gets the item, what is claimed against what is true, when audits happen, and how much the liar gains over telling the truth.

This is a simplified abstract model written for illustration. Single runs are noisy, so use the seed box to see how much results vary. The quantitative findings are in the paper draft, not in this page.

How to read the panels

  • True urgency now. Claim the server receives. Claim of agent 1, the possible liar. Under the quota mechanism the claim shown is the level the server actually sees after rewriting.
  • Agent that received the item this round. In the timeline a filled square means “got the item”; a grey column means a round thrown away by a raid.
  • Suspended: the agent cannot win. An audit came back and passed. An audit or raid caught a mismatch. A raid looked at this agent.
  • Bottom strip of the timeline: agent 1’s true urgency (grey) against its claim (colour).

Model: three agents, one item per round, only agent 1 may misreport. Types follow a Gaussian AR(1) in a latent space with three different marginals. Checks see the truth τ rounds after the decision. Mechanism parameters are scaled for these short runs and are not the paper’s values. Strategies in this demo are a small hand-written set, so “the liar loses here” does not mean no strategy could win. Honest-only R/T of exactly zero for some mechanisms is a feature of this short run, not a claim.
