# 後續方向（2026-10-06 記錄）

使用者認為三個方向都值得發展，決定先做方向一。

## 方向一：查核時機的定理（目前進行中）
- **核心原則**：要查的是「讓派遣者做出決定的那句宣稱」，不是事後的宣稱。
- **目標**：在簡化模型（例如 N=2）中證明兩件事：
  1. 到達時稽核必定可以被某種偏離策略利用。
  2. 派遣時稽核在一定條件下使說謊無利可圖。
- **預期成果**：補上目前論文缺的「一般性道理」，讓論文從 workshop 等級提升到正式會議（AAMAS、EC、ICRA）。
- **原則**：若前人已做過，不繞開，而是找出在其基礎上能做得更好的地方，或找到乾淨的漏洞。

## 方向二：強化學習訓練的對手（「專業騙子」）
- 用 RL 搜尋說謊策略，取代手寫的策略族，以檢驗派遣時稽核是否真的擋得住。
- 可以沿用 arbitration/gpu/ 的 GPU 模擬器。
- 和方向一互補：方向一給證明，方向二給實測。

## 方向三：把機器人換成 AI agent（可作為第二個作品）
- **對應結構**：
  - 稀缺資源：審查者的注意力、GPU、API 額度、人類的時間。
  - 多個 LLM agent 自報任務急迫度，可能誇大。
  - 事後可查核：任務完成後才知道當初是否真的急。
- **研究問題**：
  - LLM agent 是否會系統性地誇大或低報急迫度？
  - 用派遣時稽核原則設計多 agent 排程，效果如何？

## 相關應用（可作為動機或真實資料來源）

- 醫院護理呼叫鈴
- 雲端排程的優先序宣稱
- 災害救援無人機
- 回到原本的多機器人探勘系統（可發展成 ICRA workshop 應用論文）
